# Who changes the swarm's answer? — handoff

_Status: finished. Nothing is running. OpenAI spend $76.05 of the $150 cap (`data/live/spend_ledger.json`), including the $28.94 follow-up with a 32-report memory. The N=128 and N=256 runs were not started._

A single truth-telling speaker matters early and then stops mattering. With live gpt-6-luna listeners and a clamped truth witness, muting that witness for a 10-round game lowers the group's truth share by about 0.07 at N = 8 and N = 16, close to what a neutral copying model with the measured gain predicts. The neutral model goes wrong on the clock, though. Almost all of the effect comes from the first five rounds, and over a 202-round game the loss stays near 0.05 while the model predicts 0.42, because Luna swarms lock into near-unanimity. A follow-up with memories four times longer (32 reports instead of 8) locks in just as hard, and the witness's influence still doesn't build. That lock-in is why I don't think the planned N=128, 762-round run is worth $582 (re-priced from the $1,255 estimate); see the recommendation at the end.

## What exists and how it was checked

The code lives in `flagswarm/` and reuses the pinned upstream Flag Game (`vendor/flag_game` at `546badf`, no local diff) for rendering, crop enumeration, prompts, schedule and canonicalization; every run records the upstream commit, the local-diff hash, prompt hashes and a hash of this package's source. `theory.py` holds the exact mean recursion, the closed-form loss, a vectorized Monte Carlo of the planted copying game for both schedulers, the schedule-level forward/backward neutral predictor and temporal closeness. `llm.py` is the Responses adapter (strict `flag_report` schema, `reasoning={"effort":"none"}`, 128-token cap, `detail:"high"`, no temperature/seed/tools) plus a scripted copier behind the same interface; within one replicate namespace identical requests share one sampled answer, nothing is shared across namespaces, and the per-block call log doubles as the resume checkpoint. `game.py` runs a branch with dependency-aware concurrency that reproduces sequential histories exactly. `calibrate.py`, `qcal.py`, `manifest.py`, `runner.py`, `analyze.py` and `plot.py` implement the stages; `cli.py` is the single entry point (`python -m flagswarm.cli <cmd>`).

The 37 tests in `tests/` pass. They cover the deterministic fixture (0.0188556892 with self-contacts, 0.0190012580 without, persistent limit 0.4921875, all to 1e-10), recursion = closed form across parameters including restored windows, Monte Carlo = recursion for the mean response and finite-window recovery under both schedulers, the predictor's weak (single-drop) and full-mute predictions = exact enumeration on a tiny schedule, h = 0 having no effect under coupled randomness, and the harness invariants: a drop consumes its slot and appends nothing while the muted agent keeps listening and voting, readouts never enter memory, memory equals the last 8 delivered reports, branches agree up to the fork and diverge after it, A/A namespaces draw independent samples, a resumed call log reproduces a branch with zero new calls, and an ambiguous crop produces a byte-identical request whatever the hidden truth (PNG bytes carry no metadata; the same pixels from two flags give the same bytes). The offline stage (`data/offline/v1`) confirms the planted control against theory over 252 points (both schedulers, N = 8, 16, 32, windowed and sustained mutes): max |z| = 2.58, none above 3.

## Datasets

`data/offline/` holds simulator output, `data/scripted/` the scripted-copier harness, and `data/live/gpt-6-luna/` every provider result (calibration, panel, predictor, stages). Records carry `source`. Figures in `figures/` each have a CSV of the plotted numbers next to them.

## Calibration (gpt-6-luna, provider data)

The preflight confirmed access: requests to `gpt-6-luna` return `gpt-6-luna`, strict-schema responses parse, and the account limits are 30,000 requests/min, 180M tokens/min and 50,000 images/min. Measured usage is about 309 input and 31 output tokens per call (a crop is cheap at 150 x 100), roughly half the spec's 800/40 assumption, so every projection below is re-priced from measured usage.

Luna recognizes the full flags at 60/64 (93.8%, Wilson 0.85-0.98), passing the 0.90 gate; all four misses are Netherlands answered as Luxembourg when Luxembourg is listed first, so candidate order matters for that pair and stays counterbalanced. Validity was 100% on 5,128 calibration calls (the 0.99 gate). Crops with a distinctive detail are read correctly from an empty memory (blue -> France 1.00, orange -> Ireland 0.96), but Luna yields to a 6-2 opposing majority on almost every crop. Under the spec's thresholds only France's three blue crops qualify as true-favoring witnesses, no case has a rival-favoring witness (the best candidate, France>Peru all-red, says Peru 0.67 from an empty memory), and every case has 2-3 qualifying persuadable crops (`figures/calibration_crop_probes.png`). By the spec's rule the controlled two-witness study is therefore **unavailable** for Luna. I kept Luna rather than switching to Terra, because the spec reserves the substitution for a vision failure and this is a social ceiling, which it says to retain as a measurement. The two-witness question is instead studied in the spec's separately labeled `clamped_witness` hybrid: witness reports are fixed (truth or rival label with the calibration template sentence) while every listener is a live Luna agent holding a behavior-verified persuadable crop. The natural cohort (uniform crop positions, no behavior selection) runs alongside it.

Listener calibration on 16 separate games (7,680 probes, all valid) gives a frozen in-game copying gain q = 0.22 (95% CI 0.18-0.28), the pre-declared full-context fit. The gain depends strongly on memory occupancy: one message moves an empty-memory listener with q = 0.70, a mid-game listener with 0.22 and a listener with a full 8-report FIFO with only 0.09 (CI 0.01-0.19). Luna seems to aggregate its whole transcript rather than copy the latest report, so the single-gain neutral model is an approximation from the start (`figures/calibration_listener_gain.png`). Truth and rival messages move listeners about equally (+0.21 vs -0.22 mean change).

## Results

All numbers below are provider results unless marked. Loss D is baseline minus intervention truth share at the readout, paired within a replicate namespace; brackets are 95% intervals from a bootstrap over independent games (stratified by flag case when every case has at least two games).

**Stage 1: exhaustive ablations at N = 8 and 16, 10 rounds, 32 games per cell** (`data/live/gpt-6-luna/stage1`, 2,808 branches, $12.28). The clamped truth witness's full mute costs 0.070 [0.020, 0.125] at N = 8, 0.068 [0.021, 0.121] at N = 16 with one witness of each sign, and 0.045 [-0.006, 0.100] at N = 16 with two of each (the redundant cohort). The frozen neutral predictions were 0.102, 0.064 and 0.041, so the magnitudes match within noise (`figures/stage1_comparators.png`). Muting the clamped rival witness does almost nothing (+0.008, -0.012, -0.016), although the neutral model predicts a gain for the truth of 0.045-0.10. In natural games, where crops come from uniform positions with no behavior selection, the most truth-favoring crop's speaker matters at N = 8 (0.062 [0.004, 0.125]) and not at N = 16 (-0.008 [-0.066, 0.045]). The predicted top speaker beats a uniformly random speaker in the clamped cells (top - random 0.059 [0.016, 0.105] at N = 8), mostly because it is usually the truth witness, and it doesn't beat an opportunity-matched speaker. Within-game rankings of all N speakers correlate weakly with the observed full-mute losses: Spearman rho 0.05-0.19 for the neutral full-mute score and similar for private crop accuracy, near zero for temporal closeness, and slightly negative for the paper's S score, which ranks the gain from a new crop and gives an already-accurate witness zero by design (`figures/stage1_ranking.png`). Those correlations are near the ceiling this design allows. The scripted copier, for which the neutral predictor is nearly exact, reaches only rho 0.08-0.25 on the same games, because each mute is a single noisy replicate.

The timing result is the clearest departure from the neutral model. Pooled over the 24 clamped games that ran window arms, muting the truth witness in rounds 1-5 costs 0.146 and muting it in rounds 6-10 costs 0.026, a paired difference of 0.120 [0.034, 0.211] (`figures/stage1_windows.png`). The frozen predictor expected the late window to matter at least as much as the early one, and the scripted copier on the same games shows no early advantage. This matches the listener calibration: once a FIFO holds eight reports, one more report barely moves the listener (q = 0.09). Dose arms (drop each report with probability 0.1, 0.25, 0.5) rise with h toward the full mute in the N = 16 clamped cells but not at N = 8, and with 8 games per cell they don't resolve D(h) against h*chi.

**Stage 4: mechanism checks at N = 8 on the same games** (`data/live/gpt-6-luna/stage4`, $1.46). Fresh samples replicate the clamped truth-witness loss (0.078 [0.016, 0.145] against 0.070 in Stage 1). With country-only reports (m = 1) the witness effects become symmetric: muting the truth witness costs 0.113 [0.066, 0.148] and muting the rival witness gains 0.062 [0.023, 0.109], about what the neutral model predicts. So the missing rival effect at m = 3 is tied to the one-sentence reasons. My hypothesis is that live agents' concrete visual reasons outweigh the clamped witnesses' generic template sentence when they point the other way, but this run doesn't test that. A visible placeholder in place of the truth witness's reports, and dropping an equal number of other speakers' reports at matched times, both cost about as much as silencing the witness. The paired differences are 0.012 [-0.066, 0.090] and 0.027 [-0.074, 0.129], so this design can't separate the loss of content from the FIFO side effect.

**Stage 2: population size at 10 rounds** (`data/live/gpt-6-luna/stage2`, N = 32 with 32 games per cell and N = 64 with 16, $12.35). The truth witness's 10-round loss falls with N roughly as the neutral clock predicts: 0.070, 0.068, 0.019 [-0.012, 0.051] and -0.015 [-0.036, 0.006] for a fixed count of one witness of each sign at N = 8, 16, 32 and 64, against predictions of 0.10, 0.06, 0.03 and 0.016. The fixed-fraction cohort falls similarly (0.070, 0.045, -0.012, 0.000) (`figures/population_witness_loss.png`). At N >= 32 the 10-round effect is below what 16-32 games can resolve, as theory says it should be, so 10 rounds can't distinguish "more witnesses" from "slower clock". That needs a long horizon.

**Stage 3: clock and recovery at N = 16 over 202 rounds**, T_late = ceil(3(N-1)/(q(Z-1))) with the frozen q = 0.22, so a model-based time point (`data/live/gpt-6-luna/stage3`, 32 games, $20.43). A sustained mute of the clamped truth witness costs 0.035 [-0.025, 0.090] at round 10, 0.061 at 20, 0.074 [0.002, 0.154] at 50, 0.064 at 100 and 0.053 [-0.027, 0.137] at 202. The neutral prediction rises from 0.061 to 0.416 over the same span; even with the full-FIFO gain q = 0.09 it predicts 0.31 at round 202, far outside the interval. Restoring the witness after round 5 doesn't bring the loss back to zero as theory predicts. It stays near 0.04 through round 100 (0.018 [-0.033, 0.070] at 202), though those intervals include zero, so persistence of early harm is suggestive rather than established (`figures/stage3_clock_recovery.png`). The mechanism is lock-in. By round 202, 97% of baseline games have at most one of the 14 flexible (non-clamped) agents off the majority label and 72% have all 14 on one label, and only 3.3% of flexible agents change their answer between rounds 100 and 202. In the neutral model the lone witness keeps converting listeners indefinitely. In Luna swarms a unanimous eight-report memory doesn't move for one dissenting report.

**Stage 3 with a 32-report memory** (`data/live/gpt-6-luna/stage3_h32`, $28.94). This reran Stage 3 on the identical 32 games (same crops, schedules and clamped witnesses) with H = 32, to test whether lock-in comes from an eight-report memory that fills up and stays unanimous. The A/A arm was dropped to keep the run under the $35 limit: the full design projected to $38.71 and the three-arm version to $29.03, from a fitted token model of 194 + 22.7 tokens per memory line. The longer memory doesn't let the witness's influence build. The sustained-mute loss is 0.039 [-0.002, 0.086] at round 10, about the same as with H = 8, then falls to 0.010 at 20, -0.049 [-0.113, 0.010] at 50 and -0.055 [-0.129, 0.000] at 202. The neutral prediction is unchanged at 0.416, because the neutral copier has no memory length. Lock-in is as strong as before. By round 202, 88% of baseline games have all 14 flexible agents on one label (72% with H = 8), 97% have at most one dissenter (also 97%), and 3.1% of flexible agents change their answer between rounds 100 and 202 (3.3%). Paired by game, the H = 32 mute loss is 0.107 [0.014, 0.207] lower than the H = 8 one at round 202. That difference rests on about six games where the swarm settled on the other label: three in favor of the truth and one against with H = 8, none in favor and two against with H = 32. The paired interval excludes zero at rounds 50 and 202 but not at 100, and seven rounds were compared, so I don't read the negative H = 32 loss as an effect. Per-game SD at round 202 is 0.21 (0.29 with H = 8). Restoring the witness after round 5 tracks the sustained mute throughout (`figures/stage3_memory_h8_vs_h32.png`, numbers in `analysis/memory_compare.csv`).

**Offline and scripted references.** The planted copying simulator matches the exact recursion for both schedulers (`figures/offline_planted_vs_theory.png`), and the analytic curves (`figures/offline_scaling_curves.png`) show what the population question looks like in theory: for a fixed witness count the persistent loss approaches 0.5 as N grows, but the 10-round loss shrinks because the response takes ~N times longer to appear; for a fixed fraction even the eventual loss shrinks. The scripted copier on the Stage 1 games (`data/scripted/gpt-6-luna/stage1`, no provider calls) behaves like the neutral model: the rival-witness mute helps the truth (-0.05 to -0.06) and late windows matter as much as early ones, which isolates the two live departures above as LLM behavior rather than harness artifacts.

## Caveats

The controlled two-witness study as specified is unavailable for Luna, so every witness result comes from the clamped hybrid, whose witnesses are fixed reports with a template sentence rather than LLM agents with a crop; that is the spec's separately labeled diagnostic, not its primary design. Natural-cohort effects are small and mostly unresolved. The independent A/A contrast averages +0.023 +/- 0.011 at round 10 over 352 games (2.1 SE), with 2-4 of 12 cells individually above zero depending on the interval method. The namespaces sample identically at round 0 (+0.006 +/- 0.011) and round 5, so I read this as heavy-tailed lock-in outcomes plus multiplicity, but it is unresolved; it doesn't bias the mute contrasts, which are paired with a baseline in the same namespace. Window, dose and omission arms ran on 8 games per cell. Per-game paired SD of the truth-witness contrast is 0.17-0.21, so by the spec's power formula a 0.03 contrast needs roughly 250-400 independent games.

## Decisions made without the user

I kept gpt-6-luna instead of piloting Terra, because Luna passed the vision floor and the spec reserves substitution for that failure. I used the clamped hybrid plus the natural cohort once the panel came back without rival witnesses. q was fixed by a rule written into `qcal.py` before any intervention ran (the full-context fit); zero-history and full-FIFO fits are reported as diagnostics. In natural games the named targets are the most and least truth-favoring crops by crop-only rate (schedule-blind, ties broken by a seeded draw). Discovery sampled 12 of 13 crops by proportional stratification where needed. Stage 3 ran at N = 16 rather than N = 32, as the cheapest decisive long-horizon test. I fixed a bootstrap bug that gave zero-width intervals for single-game strata before writing any results. Stage 3 was killed once by the container's 8 GB memory limit (other sessions hold about 5 GB); its spend was reconstructed from the call logs into the ledger, the cache now keeps slim answers, and the resumed run re-billed nothing. `orch.toml` in this folder exists only so `orch session` can run here; the project creates no pods.

## Should the N=128 run happen?

I recommend not running it. It was designed to see a lone witness's influence build up over 762 rounds, about three relaxation times in the neutral model at q = 0.5, where theory predicts a loss of 0.47. At N = 16, over the equivalent horizon for the measured gain, that build-up doesn't happen: the loss levels off at about 0.05 by round 20 while theory heads to 0.42, because the swarm locks into consensus. At N = 64 the 10-round effect is already indistinguishable from zero. So the most likely outcome at N = 128 is a loss near zero, measured with a per-game SD near 0.29 (the N = 16 long-horizon value, carried over as a projection) over 64 games, a standard error of about 0.036,, for $582 at measured token usage and 7-17 hours of wall time (`python -m flagswarm.cli estimate` re-prices the spec's rows). That would confirm a null the N = 16 run already shows. I ran the cheap test I proposed for changing my mind, the same N = 16 design with a 32-report memory. It came back negative. Late-game losses are near zero or slightly negative, and lock-in is at least as strong as with eight reports, so saturation of a short memory isn't what stops the build-up. Luna listeners just stop moving once their peers agree. That strengthens the case against N = 128, which would run the same eight-report memory over more rounds. I'd only reconsider for a listener that the calibration shows still copies a lone dissenting report against a unanimous memory, which Luna doesn't (its gain drops from 0.70 with an empty memory to 0.09 with a full one).

## Reproduce

`uv sync`, then `uv run pytest -q` (no provider calls). Stages in order: `python -m flagswarm.cli offline | preflight | calibrate | crop-only | freeze-panel | qcal`, then `manifest` / `estimate` / `run` / `analyze` per stage (Stages 2-4 are built by `manifest.build_stage2/3/4` and analyzed with `analyze.analyze`, `analyze_stage3`, `analyze_stage4`). `run` resumes by default. The 32-report variant is `python -m flagswarm.cli manifest --stage stage3_h32 --H 32 --no-aa`, then `run --stage stage3_h32 --max-usd 35`, `analyze.analyze_stage3`, and `python -m flagswarm.plot memory`, which also writes the H = 8 vs 32 comparison table. Figures: `python -m flagswarm.plot offline|calibration|stage1|stage3|population|memory`.
